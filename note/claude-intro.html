001_入門與設定

· 1 篇

1. 入門與設定：雲端 Claude、Claude Code、模型與權限

全民 AI 手冊 · 章節 1–3 · 00:00–04:18
一句話總結

先分清「雲端 Claude（隨處問答）」和「Claude Code（跑在本機、能讀改檔案）」，再把個人背景一次設好、選對模型與權限模式，之後每次提問都省力又省 Token。

你會學到
  • 註冊訂閱、以及雲端 Claude 與 Claude Code 的根本差別
  • 用「帳戶設定＋記憶」讓 Claude 永遠記得你的背景，不必每次重講
  • Claude 模型家族怎麼挑、「投入程度」與「權限模式」各是什麼
  • 為什麼要把 PDF 先轉成 Markdown 再丟給 AI

內容筆記

雲端 Claude vs. Claude Code（最關鍵的分野）⏱ 00:00

註冊很簡單：用 Google 帳號到 Claude 首頁註冊，選訂閱方案。

免費版 vs. 付費版

免費版已有不少功能；但想讓 Claude 操作你電腦上的檔案與工具，要訂閱 Pro 以上方案。填好信用卡、點「訂閱」，再下載安裝桌面版軟體即可。

打開桌面版後，左上角有一個 Claude ↔ Code 的切換開關，兩者差別在「程式跑在哪裡」：

雲端 ClaudeClaude Code
運作位置官方雲端伺服器你的電腦本機
能不能讀改本機檔案否能（直接讀取、修改電腦裡的檔案）
典型用途日常提問、文件、簡報開發 App、建立自動化工具
電腦關機時不受影響、照常用停擺（任務跑在本機）

設定個人偏好與記憶 ⏱ 01:37

不想每次提問都重講自己的背景？到「設定」→「帳戶」分頁：上傳頭像、填全名與暱稱、描述工作性質，並在下方填「想讓 Claude 預先知道的資訊」——在哪裡工作、工作內容、以及回覆時應遵守的原則。

兩種「記住你」的機制
  • 帳戶設定裡的個人資訊：你主動輸入、固定不變的背景與原則。
  • 記憶（Memory）：Claude 在對話過程中，自動把與你相關的重要資訊記錄下來。

模型家族、投入程度、權限模式 ⏱ 02:18

提問前可在底下指定一個專案資料夾當參考，右邊下拉選單選「負責思考回答的模型」。Claude 是一個模型家族：

模型定位
Haiku速度最快，適合簡單小任務
Sonnet能力與速度最平衡，日常工作主力（示範選 Sonnet 5.5）
Opus邏輯複雜、需長時間深度思考的任務
Fable更聰明一籌，但消耗更多額度
  • 投入程度：Claude 會投入多少時間與運算資源去思考分析，一般維持預設「中」即可。
  • 權限模式：選「手動」時，Claude 每次改檔或執行指令前都會先跟你確認；嫌囉嗦就切「自動」。

把 PDF 先轉 Markdown 再用 ⏱ 03:00

小芳拿到一份內容很多的「認養作業手冊」PDF。可以直接把 PDF 拖進對話框，但——

省 Token 的實務習慣

PDF 的初衷是「給人看的視覺排版」。常用文件先請 Claude 轉成 Markdown，AI 解析內容與結構更有效率、也更省 Token。轉好的文件會顯示在右側窗格，點右上角「下載」即可存成 .md 重複使用。

關鍵詞

  • Claude Code：跑在本機、能直接讀寫電腦檔案的版本，用來開發與自動化。
  • 投入程度（Effort）：Claude 花多少思考時間與運算資源，預設「中」。
  • 權限模式：手動＝每次動作前先確認；自動＝不再逐一確認。
  • 記憶（Memory）：Claude 在對話中自動保存與你相關的重要資訊。
  • Markdown：純文字的輕量標記格式，AI 解析比 PDF 省 Token。

可執行要點

📝 隨堂測驗（點選項作答）
雲端 Claude 與 Claude Code 最根本的差別是什麼？
Code 跑在電腦本機，可直接讀取與修改本機檔案，常用於開發與自動化；雲端 Claude 跑在官方伺服器。
下列哪個模型『更聰明但更耗額度』？
Fable 聰明程度更勝一籌，但相對消耗更多額度。
為什麼建議把常用 PDF 先轉成 Markdown？
PDF 以視覺排版為主，轉成 Markdown 讓 AI 更有效率解析內容結構，並節省 Token。

002_高效提問與專案

· 1 篇

2. 高效提問公式、對話技巧與專案工作空間

全民 AI 手冊 · 章節 4–5 · 04:18–07:18
一句話總結

用「背景／任務目標／具體要求／驗證方式／輸出格式」五要素寫提示詞，搭配四個省 Token 的對話習慣；重複性的工作則開一個「專案」當長期工作空間，資料與規則一次放好、每次自動帶入。

你會學到
  • 一條能大幅提升回答品質的「五要素提問公式」
  • 四個讓對話更準、更省額度的習慣
  • 用「專案」打造獨立工作空間，省去每次重傳檔案

內容筆記

五要素提問公式 ⏱ 04:18

先開一個新對話（別把不同任務全塞同一個對話，會互相干擾、也浪費 Token）。把文件拉進來後，用這個公式寫提示詞：

提問五要素
  1. 背景 — 你是誰、情境是什麼
  2. 任務目標 — 要達成什麼
  3. 具體要求 — 細節條件、限制
  4. 驗證方式 — 怎麼算做對（例如附上出處）
  5. 輸出格式 — 要表格、清單還是摘要

按這個公式，Claude 會給出條理分明、附章節出處的結果。若追問與上下文有關，直接在同一對話底下continue即可，不必另開。

四個對話技巧（都跟「省 Token、保準度」有關）⏱ 05:10

跟 AI 對話的四個好習慣
  1. 一次把需求說清楚——別像傳 Line 一樣拆成好幾則慢慢補；每送一次，Claude 就把整段對話重新處理一遍，浪費 Token 又容易偏題。
  2. 對話別拉太長——Claude 一次能記住的上下文有上限，太長會讓重要資訊被淹沒。
  3. 對話中別切換模型——Claude 有快取（Cache）暫存對話以省運算；中途換模型會讓快取失效，被迫重讀上下文、浪費 Token。
  4. 隨時注意用量——額度分「五小時」與「每週」兩個指標，超過要等下次重設。

建立專案工作空間 ⏱ 06:11

接下來幾個月的工作都圍繞「提升認養率」，若每次都要重傳手冊很麻煩。改用 Claude 的「專案」功能建一個獨立工作空間：

  1. 取好記的專案名稱與明確具體的目標
  2. 左下角「新增」，把作業手冊與待認養動物表格清單一起上傳，點「建立」
  3. 右上角「指示」欄寫這個專案的專屬規則（例如「如何介紹毛孩」「毛孩資料必須以清單檔案為準」）
  4. 確認「記憶」區塊已開啟（讓 Claude 主動保存對話關鍵內容）

設定好後，因為手冊與清單已在專案裡，Claude 能立即根據背景知識產出完整的「毛孩介紹卡」，不必再重貼資料。

關鍵詞

  • 提問五要素：背景、任務目標、具體要求、驗證方式、輸出格式。
  • 快取（Cache）：暫存對話以省運算；中途切換模型會使其失效。
  • 額度指標：五小時額度與每週額度兩種，超過需等重設。
  • 專案（Project）：放固定資料與規則的獨立工作空間，提問自動帶入。
  • 指示欄：寫在專案裡、對該專案所有對話生效的專屬規則。

可執行要點

📝 隨堂測驗（點選項作答）
提問五要素不包含下列哪一項？
五要素是背景、任務目標、具體要求、驗證方式、輸出格式。
為什麼不建議在同一個對話中途切換模型？
切換模型會使暫存對話的快取失效，Claude 必須重新讀取上下文，造成 Token 浪費。
Claude 的用量額度分成哪兩個指標？
額度分『五小時』與『每週』兩個指標，超過要等下次重設。

003_成品白板與子代理

· 1 篇

3. 成品（Artifacts）、白板與子代理研究

全民 AI 手冊 · 章節 6–7 · 07:18–09:12
一句話總結

Claude 不只回答，還能直接生出「成品（Artifacts）」——用白板把雜亂筆記整理成流程圖、用「評論」就單一步驟追問風險；研究大題目則派「子代理」分頭並行蒐集、再統整成清單。

你會學到
  • 什麼是「成品（Artifacts）」與「白板」畫布
  • 怎麼讓 Claude 幫你把亂筆記整理成結構化流程圖
  • 「評論」功能如何就某個環節請 Claude 點出風險
  • 「子代理（Subagent）」如何把一個大研究並行拆解

內容筆記

成品與白板 ⏱ 07:18

除了問答，Claude 能直接幫你生成完整的成品（Artifact）。側邊欄進入「成品」分頁，啟用「白板」——一張可無限延伸的畫布：

  • 用底部工具列建立方塊、文字、便利貼等圖形
  • 每張卡片可自由改外觀（如顏色）
  • 點卡片四周的圓點可在旁邊延伸新卡片
白板最強的地方：交給 Claude 來建

把你的「會議筆記」拉進文字框，請 Claude「用白板功能整理分類」，稍待就會生出一張結構清楚的流程圖。右上角可展開，裡面每個方格都能編輯文字或延伸新方塊。

用「評論」就單點追問

對某個環節不放心時，用「評論」功能就「這個步驟」向 Claude 提問，Claude 會立即在旁邊點出潛在風險與注意事項——等於邊畫邊做風險檢查。

子代理進行研究 ⏱ 08:45

小芳想知道「別的收容所用哪些方法提高認養率」，但方向很多、一個個查太慢。

子代理（Subagent）= Claude 派出去的分身

請 Claude 派出子代理，把不同研究方向同時分頭找齊，最後由 Claude 統一梳理成一份重點清單。多方向並行，整個流程事半功倍。

關鍵詞

  • 成品（Artifact）：Claude 直接生成的完整產物（白板、文件、簡報、儀表板等），不只是文字回答。
  • 白板（Whiteboard）：可無限延伸的畫布，放方塊／文字／便利貼，可由 Claude 代為規劃建構。
  • 評論（Comment）：就成品中某一步驟向 Claude 定點追問風險與建議。
  • 子代理（Subagent）：Claude 派出的分身助手，並行處理多個研究方向後統整。

可執行要點

🎴 單字卡（點卡片翻面）

004_連接服務技能與排程

· 1 篇

4. 連接郵件日曆（MCP）、建立技能（Skills）與排程任務

全民 AI 手冊 · 章節 8–10 · 09:12–12:46
一句話總結

用 MCP 把 Claude 接上 Gmail、日曆、雲端硬碟，它就能讀信、擬草稿、登記行程；把重複做兩次以上的流程打包成「技能（Skill）」，再用「排程任務」讓它每天自動跑。

你會學到
  • 什麼是 MCP，以及如何一鍵串接 Gmail／Google 日曆／雲端硬碟
  • 「技能（Skill）」是什麼、怎麼建立與觸發、它其實就是一份 Markdown
  • 用「排程任務」讓技能定時自動執行

內容筆記

用 MCP 連接電子郵件與日曆 ⏱ 09:12

小芳的信箱每天塞滿認養詢問信，光回信就耗掉一下午。解法是把 Claude 接上她的信箱——透過一種叫 MCP 的技術。

MCP 串接非常簡單

點 Gmail 旁邊的「＋」號，Claude 會自動開瀏覽器協助完成連接器設定與帳號授權。接著可順手把 Google 日曆與雲端硬碟一起串進來。

串好後做個測試——請 Claude「把所有詢問認養的來信整理成表格，信中若提到想參觀的時間就登記到 Google 日曆」。稍待，Claude 就：

  • 把所有詢問信整理成表格
  • 在 Gmail 裡每封信都附上寫好的回覆草稿
  • 把民眾預約的參觀時段自動記進行事曆

建立技能（Skills）⏱ 10:22

每次請 Claude 回信都要重講細節很煩。

兩次以上就該打包成 Skill

任何事只要你會重複做兩次以上，就適合打包成一個 Skill（技能）＝一套固定的標準作業流程。

做法：把回信的所有步驟與注意事項整理成一份文件、拉進輸入框，請 Claude「根據這份文件建立一個回覆郵件的技能」。之後觸發方式有兩種：

  • 輸入斜線 /，從選單選「回覆郵件」技能
  • 更省事：直接交代 Claude「到信箱回信給蔡小姐」，它會自動啟用對應技能、寫好回信存成草稿讓你最後檢查
技能其實就是一份 Markdown

側邊欄點「外掛程式」→ 切到 Skills 分頁，可以：用「新增」上傳別人分享的技能、把技能暫時停用或刪除。打開技能本身，會發現它就是一份 Markdown 文件，裡面的流程步驟都能手動編輯。

設定排程任務 ⏱ 12:00

技能建好了，但你不主動吩咐它就不會跑。可在專案內建自動排程任務：自訂執行內容、觸發頻率與時間；也能直接在對話框用白話描述，例如「每天早上 9 點到我的信箱，替每封信擬好回信草稿」。之後到左側「排程任務」可暫停、刪除、修改觸發時間與內容。

關鍵詞

  • MCP：把 Claude 連上第三方服務（Gmail、日曆、雲端硬碟、圖片平台等）的連接技術。
  • 連接器（Connector）：某個外部服務的 MCP 連線設定，授權後 Claude 即可操作該服務。
  • 技能（Skill）：打包成標準作業流程的 Markdown 文件，可被 / 或自然語言觸發。
  • 排程任務：讓指定工作（含技能）在設定的時間自動執行。

可執行要點

透過 MCP 串接第三方服務；點服務旁的『＋』即可授權連接。
影片建議『什麼情況』就該把流程打包成 Skill？

005_試算表與文件編輯

· 1 篇

5. 試算表與文件編輯：整理 Excel、條件格式、圖表與改寫文案
